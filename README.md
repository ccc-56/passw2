# passw2

Cheap, disposable outbound proxy node on AWS Lightsail in Seoul (`ap-northeast-2`)
with **two inbounds on one box**:

| inbound | transport | when to use |
| --- | --- | --- |
| Xray-core **VLESS + REALITY** (XTLS-Vision) | 443/tcp | default; lowest overhead, best stealth |
| **Hysteria2** | 443/udp (QUIC) | lossy / throttled evenings; recovers much faster than TCP |

Every device gets its **own credentials** (`users` variable), so one leaked
link can be revoked without touching the others.

Sister project: [passw1](https://github.com/ccc-56/passw1) is the single-inbound
Tokyo node this repo was forked from. The two are fully independent (separate
region, state bucket, keys and IP) and can run side by side.

## Cost

| item | monthly |
| --- | --- |
| Lightsail `nano_3_0` (0.5 GB / 2 vCPU, **1 TB egress included**) | $5.00 |
| Static IPv4 (while attached to a running instance) | $0.00 |
| S3 state bucket (a few KB) | ~$0.00 |

Prorated hourly, so a node that only lives for a weekend costs roughly $0.25.

Lightsail is used instead of EC2 on purpose: EC2 charges ~$0.114/GB egress from
Seoul beyond the 100 GB free tier, i.e. streaming video from an EC2 proxy easily
costs 10–20x the instance itself. `micro_3_0` ($7, 2 TB) and `small_3_0` ($12,
3 TB) are drop-in upgrades via `bundle_id` if 1 TB is not enough.

## Why VLESS + REALITY *and* Hysteria2

REALITY completes the TLS handshake against a real third-party site
(`reality_dest`), so the node presents a genuine certificate for a genuine
domain and has no TLS fingerprint of its own. No domain name, no ACME
certificate and no CDN are required, and active probing of the port sees only
the impersonated site.

Hysteria2 runs QUIC over UDP with its own congestion controller (Brutal, or
BBR when the client does not declare a bandwidth). On a congested China→Korea
path with 5–20 % loss it typically sustains several times the throughput of a
TCP connection, and it is unaffected by TCP-specific QoS. It needs a TLS cert,
so Terraform generates a 10-year self-signed one and clients pin its SHA-256
(`pinSHA256`); unauthenticated probes of the UDP port get a reverse proxy of
the same site REALITY impersonates. If your ISP throttles QUIC, fall back to
the VLESS entry or move `hysteria_port` off 443.

## Usage

Prerequisites: `terraform`, `aws` CLI with credentials, `openssl`, `curl`,
`unzip`, `jq`, `basenc` (coreutils). Optional: `qrencode` for QR codes.

```bash
./scripts/up.sh        # create/update the node, print vless:// + hysteria2:// links per device
./scripts/verify.sh    # prove traffic really exits through the node over both inbounds
./scripts/links.sh     # reprint the share links and rewrite clients/   (QR=1 for QR codes)
./scripts/rotate-ip.sh # new IPv4 if the current one gets blocked
./scripts/ssh.sh       # shell on the node (e.g. journalctl -u xray -u hysteria-server)
./scripts/down.sh      # destroy the node, bill back to zero
```

`clients/` (git-ignored) gets `share-links.txt` plus one directory per device
with its share links, an xray-core client config and an official Hysteria2
client config. Import the share links into v2rayN / Nekoray / sing-box /
Shadowrocket / Clash.Meta directly (all of them understand both URI schemes).

### Devices

```hcl
# terraform/terraform.tfvars
users = ["phone", "laptop", "tablet"]
```

Adding a name issues fresh credentials for it; removing one revokes it. Either
change rewrites the node's config and therefore replaces the instance (a few
minutes of downtime, IP unchanged). Existing devices keep their credentials.

### State and stable credentials

Terraform state lives in `s3://passw2-tfstate-<account-id>` (created
automatically, override with `TF_STATE_BUCKET`). `down.sh` deletes only the
billed AWS resources and leaves the UUIDs, Hysteria2 passwords, the REALITY
keypair and the Hysteria2 certificate in state, so the next `up.sh` — even from
a different machine — issues the *same* credentials and your previously imported
client entries keep working after a one-line IP edit (or just re-import).

The REALITY private key is 32 random bytes generated by Terraform; the public
key clients need is derived from it with `openssl` in `scripts/common.sh`, which
is why the server never has to report it back. Likewise the Hysteria2 pin is
computed locally from the certificate stored in state.

## Operational notes

- Only ports 22 (`ssh_allowed_cidrs`, default open — narrow it), 443/tcp and
  `hysteria_port`/udp are reachable; Lightsail's default port 80 rule is removed.
- BBR + `fq`, enlarged TCP buffers and 16 MB UDP socket buffers (QUIC needs
  them) are applied via cloud-init. A 1 GB swapfile protects the 512 MB node;
  xray + hysteria together idle at ~40 MB.
- Watch the 1 TB allowance in the Lightsail console; overage is $0.09/GB. Both
  inbounds share it.
- If throughput collapses but the port is still open, the IP is likely throttled
  rather than blocked — try the Hysteria2 entry first, then `rotate-ip.sh`.
- Sensitive values (`reality_private_key`, `hysteria_passwords`,
  `ssh_private_key`) are Terraform outputs marked sensitive and stored in the
  encrypted state bucket. Anyone with a share link has full use of the node;
  treat each one as a password.
